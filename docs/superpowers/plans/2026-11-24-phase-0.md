# Phase 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold, tested maths engine, deploy pipeline and one prototype lesson (Lesson 10 + W12) for the Rational Points study companion.

**Architecture:** Astro static site with MDX lessons in a typed content collection; Preact islands for widgets; a framework-free TypeScript maths engine in `src/lib/math` that widgets and build-time pages both import. All displayed numbers come from the engine.

**Tech Stack:** Astro, MDX, Preact, KaTeX (remark-math + rehype-katex), Vitest, Playwright, GitHub Actions (withastro/action + deploy-pages).

**Spec:** `docs/superpowers/specs/2026-11-24-phase-0-design.md`, `docs/research-report.md`

## Global Constraints

- `site: https://nkaditya1729.github.io`, `base: /rational-points`. All internal links go through `import.meta.env.BASE_URL`.
- `docs/private/` is git-ignored before the first commit; no PDF is ever staged.
- No text, proof, figure or exercise statement copied from either book. Cite printed pages only.
- Exact BigInt rationals for every displayed number; floats only for drawing.
- Okabe–Ito palette; dark and light themes; 44px touch targets; `prefers-reduced-motion` → step mode.
- Reading cards cite printed pages; PDF lookup uses `docs/page-map.md` (offset is not constant).

## Review Focus

1. Dragging P onto Q in W12 → widget must switch to the tangent (doubling), not divide by zero.
2. P and Q with the same x and opposite y → result is O, shown as a badge, no NaN line.
3. Sliders set a, b with 4a³+27b²=0 → singular warning, group law disabled.
4. Huge numerators after repeated doubling → Rational stays exact; UI truncates display with digit count, never overflows the layout at 390px.
5. Site opened under `/rational-points/` sub-path → every asset and link resolves (no root-relative `/` links).

Tests for 1–3 live in `curveQ.test.ts` (engine) and the Playwright spec (4, 5).

### Task 2: Maths engine (TDD)

**Files:** `src/lib/math/{rational,modint,curveQ,curveFp,height,nagellLutz,descent,pointCount,ecm,modular}.ts`, each with `*.test.ts`.

**Interfaces (produced):**
- `class Rational { n: bigint; d: bigint; static of(n, d?); static parse(s); add/sub/mul/div/neg/eq/isZero/sign; toString(); toNumber() }`
- `type PointQ = { x: Rational; y: Rational } | null` (null = O)
- `class CurveQ { constructor(a2, a4, a6) /* y² = x³+a2x²+a4x+a6 */; disc(); isSingular(); has(P); neg(P); add(P,Q); mul(n,P); third(P,Q) /* P∗Q */ ; order(P, max=12) }`
- `class CurveFp { constructor(a2,a4,a6,p); points(); count(); add; mul }`, `countCubicFermat(p)` for x³+y³=1.
- `height(P): number`, `torsionPoints(E): PointQ[]`, `twoDescentRank(a,b): {rank:number|null, alpha:bigint[], alphaBar:bigint[], undecided:bigint[]}` for y²=x³+ax²+bx.
- `ecm(n, {curves, B}): bigint|null`, `pollardPm1(n,B)`, `eta11Coefficients(N): number[]`, `apFromCount(E,p)`.

- [ ] Tests carry every value in the master prompt: Z/2×Z/2 and rank 0 for y²=x³−x; Z/7 from (3,8) on y²=x³−43x+166; Z/6 on y²=x³+1; 2(3,5)=(129/100,−383/1000) on y²=x³−2; the 16 integer points of y²=x³+17 with x ≤ 5234; (1,2)+(3,4)=(−3,2) on y²=x³−7x+10; Hasse for all p<1000; 6 affine points of x³+y³=1 over F₇; ECM finds 26927 | 1715761513; a_p(11a), p≤50, equals the η-product coefficients (11a model y²+y=x³−x², counted directly; p=11 excluded as bad).
- [ ] Review-focus tests: add(P,P) = double; add(P,−P) = O; singular curve throws on group ops.
- [ ] `npm test` green.
